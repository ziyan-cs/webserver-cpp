# Reactor Core

## 目标

建立事件驱动的基础组件，验证 fd 事件从注册到回调的流程。

## 结果

- 实现 `Channel`、`Epoll` 和 `EventLoop` 的初版。
- 使用管道测试读事件的注册与分发；此前 Debug 构建和测试通过。
- `Config` 和 `Logger` 的初版也已建立并添加基础测试。

## 关键问题

### 头文件循环包含

**现象**：`Channel.h` 和 `EventLoop.h` 相互包含，导致类型未声明；放在命名空间外的前向声明也指向了错误的类型。

**处理**：在 `core` 命名空间内前向声明，在调用成员函数的 `.cpp` 中包含完整定义。

### 管道测试阻塞

**现象**：先调用 `loop()`，测试一直等待，后面的写入无法执行。

**原因**：事件循环等待管道可读，而写入在同一线程的阻塞调用之后。

**处理**：先向管道写入数据，再进入事件循环。读回调执行后调用 `stop()`。

### Channel 生命周期

**风险**：Channel 销毁后，如果 EventLoop 仍保存它的指针，后续分发可能访问已销毁对象。

**处理**：Channel 不拥有 fd；销毁前从事件循环移除，并保证 EventLoop 在 Channel 使用期间有效。fd 由其拥有者关闭。

## 设计决定

- `Epoll` 管理自己的 epoll fd；`EventLoop` 不拥有传入的 Epoll 或注册的 Channel。
- 修改关注事件后，显式调用 `Channel::update()` 同步到事件循环。
- 使用单例访问配置和日志；日志暂时输出到标准输出。
